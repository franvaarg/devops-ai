# Deployment

Target: static Vite frontend on Vercel, one Node 22+ Express backend on Render, managed PostgreSQL, Gemini, Brevo and optional Stripe. Railway/Docker are compatible deployment targets but have not been live-tested. Next.js is not required. Keep billing disabled for initial staging.

Install locked dependencies with `npm ci` independently in backend/frontend. Run `node scripts/release-check.cjs` from repository root; it performs backend syntax validation, fixture validation, unit/API/security tests, isolated PostgreSQL tests, ESLint, TypeScript, production build and both npm audits. PostgreSQL server binaries are needed for integration tests; set PG_TEST_BIN as necessary. Backend JavaScript has syntax checks plus runtime tests, not TypeScript or an ESLint configuration. Browser verification uses `frontend/scripts/verify-journey.cjs` and `verify-resilience.cjs` with externally installed Playwright and axe; set PLAYWRIGHT_MODULE and AXE_MODULE when needed.

Backend environment: NODE_ENV=production; PORT from hosting; strong random JWT_SECRET (32+ characters); JWT_EXPIRES_IN; DATABASE_URL with verified TLS; AI_PROVIDER=gemini; GEMINI_API_KEY; verified GEMINI_MODEL; HTTPS FRONTEND_URL; exact comma-separated HTTPS CORS_ORIGINS; correctly measured TRUST_PROXY_HOPS; BREVO_API_KEY and real verified EMAIL_FROM. BILLING_ENABLED=false until live gates pass. Stripe settings are in BILLING.md. Never copy .env.example placeholders into production. DB_* local overrides do not override DATABASE_URL.

Frontend build environment: VITE_API_BASE_URL set to the HTTPS API origin; VITE_LEGAL_NAME, VITE_SUPPORT_EMAIL, VITE_PRIVACY_URL, VITE_TERMS_URL configured with approved real values before public/paid launch. Frontend values are public and must contain no credentials. `frontend/env` is a historical nonstandard file: Vite does not automatically load it. Use real hosting environment variables or a gitignored `.env.local`.

Render: root backend, build `npm ci --omit=dev`, start `npm start`, readiness path `/health/ready`. Apply migrations separately from a full reviewed checkout after backup/staging verification. Configure shutdown grace greater than 60 seconds and a database connection budget accounting for all instances/jobs. If platform grace is shorter, validate interrupted-request recovery and reservation expiry explicitly. Liveness `/health/live` does not establish database/provider availability. Readiness checks schema/connectivity but not external AI, email or billing.

Vercel: root frontend, build `npm run build`, output dist. Rewrites support password-reset links and client entry paths. Response headers deny framing/sniffing, suppress referrers (including reset URLs), restrict unused browser permissions and enable HSTS. API responses are no-store. CSP remains to be tailored/tested for the actual deployment origins; no claim of complete XSS prevention. Verify security headers on the actual domains after publishing.

Docker: configure repository POSTGRES_PASSWORD plus backend/.env, then use `docker compose config` before starting. Never use `down -v` for upgrades. Fresh volumes execute init and migrations 003–005; existing volumes need the explicit migration procedure. Backend runs as unprivileged node with direct signal delivery. Nginx serves static content and proxies /api on the Docker network; externally terminate HTTPS. Docker images/Compose runtime have not been built or deployed in this session.

Deploy order: green release checks; approved backup/restore evidence; drain analyses/checkouts; migration; backend; configuration/readiness; frontend; synthetic smoke users; monitor. Deployment changes to real services were not performed. Read BACKUP_RESTORE.md for compatible rollback.
